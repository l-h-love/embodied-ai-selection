## 示例：一条"合格的学习记录"长什么样

> 下面这条用你自己 2026-08-20 在 m260c 上做录音功能的真实经历改写，供对照。**注意它包含报错和弯路，这才是评审想看的东西。**

## 2026-08-20（周四） 主题：M260C 语音模块新增「自定义录音回复」

**今日目标（开始前写）**
- 让机器狗在听到指定口令（如"你好"）时播放我事先录好的音频，而不是用 TTS 合成。

**时间投入**：约 4 h

**具体做了什么**
```bash
python voice_agent.py --record-live        # 交互式录音：按 1 开始 / 再按 1 结束
python voice_agent.py --record 你好        # 录音 3 秒并绑定口令"你好"
python voice_agent.py --list-recordings    # 查看已绑定口令
```
- 新增 `audio_recorder.py`：用 `sounddevice.InputStream` 回调采音（16kHz 单声道、与 ASR 同源），按时间戳保存 wav；
- 在 `voice_agent.match_command()` 里加入录音命中分支：命中则播放录音替代 TTS；若口令同时是动作命令，则**播放录音并照常执行动作**；
- 静音保护：RMS < 300 直接取消，不保存垃圾文件；
- Windows 用 `winsound`、Linux 用 `ffplay/aplay/paplay`，与 SAPI 共用一个播放队列，避免两个声音叠在一起。

**遇到的报错（原文）**
```
TypeError: sequence item 0: expected str instance, numpy.ndarray found
```

**怎么解决的**
- 原因是采到的 chunks 是 `numpy.ndarray`，我却用 `b"".join()` 拼接；
- 改成先 `np.concatenate` 再转 `int16` 字节流写入 wav；
- 顺带修了一个老问题：SAPI 初始化失败时队列仍然被使用。

**结果验证**
- 全部 `.py` 语法检查通过；
- 模拟按键测试：按 1 开始 → 采到数据 → 再按 1 保存 → 按 2 回放 → 按 q 退出，文件正确写入 `recordings/`；
- 端到端 mock 硬件 4 个场景全通过：纯录音 / 录音+动作 / 无录音命令 / 未知文本兜底；
- 录了两段真机音频：`rec_20260820_142013.wav`、`rec_20260820_142333.wav`。

**还没解决**
- 固件不支持运行时修改唤醒词（返回 `code=107`），只能用固定唤醒词"小微小微"；
- 在线 ASR 受限，当前依赖纯离线 Vosk，长句识别准确率一般；
- "口令包含"匹配太宽松，容易误命中（例：说"你好呀"也会命中"你好"）。

**明日计划**
- 收紧口令匹配规则；补充口令冲突的优先级设计。

**一句话反思**
- 之前以为难点在"录音"，实际难点在"播放与 TTS 抢音频设备"和"任务状态机"——**先跑通最小闭环，再处理并发与状态**。
