# 工作汇报（OKR 方式）

> 选拔说明原话：**「工作过程要留痕，工作汇报推荐使用 OKR 方式呈现。」**
> 与 `01_学习记录.md` 的分工：**学习记录写"我怎么做"（过程/报错/弯路），OKR 汇报写"我做到了什么"（结果/数据/证据）。**

---

## 一、为什么用 OKR（30 秒版，面试可能问你）

- **O（Objective）**：定性、有方向感的目标（如"在选拔截止前独立完成一个可复现的机器人视觉小闭环"）；
- **KR（Key Results）**：3–4 个**可量化、可验证**的结果（如"Ubuntu 双系统启动成功并通过 nvidia-smi 验证"）；
- 每条 KR 必须能被**一张截图、一条命令输出或一个文件**证明——这正好满足"留痕"要求；
- 汇报里同时写**进展百分比 / 证据链接 / 风险 / 下一步**，比流水账有用得多。

---

## 二、模板 A：每日 3 行（发群里 / 写文档都够用）

```markdown
## YYYY-MM-DD

- **今日完成**：______（对应哪个 KR？给数字或文件）
- **遇到问题**：______（原文报错 / 卡在哪一步）
- **明日计划**：______（一条最关键的）
```

## 四、示例：把你 8 月的真实工作转成 OKR（可直接对照改写）

> 素材来源：你 8/17–8/23 在 `D:\project\m260c` 上的工作（自定义录音回复功能）。

**O：让机器狗语音模块具备"可自定义语音回复"能力，并完成向 RK3588 部署的最后准备**

| KR | 目标值 | 当前值 | 状态 | 证据 |
|---|---|---|---|---|
| KR1 录音功能可用 | 按键录制/回放/列表/删除 4 个入口全部可用 | 4/4 可用 | 🟢 | `audio_recorder.py`、`voice_agent.py --record-live` |
| KR2 口令绑定闭环 | 口令我录即播，且不影响动作指令 | mock 4 场景 + 2 段真机音频 | 🟢 | `recordings/rec_20260820_*.wav`、`index.json` |
| KR3 跨平台兼容 | Windows + Linux 均可播放 | 双平台分支已实现 | 🟡 | `DEPLOY.md` 3.5 节（Linux 依赖 ffplay/aplay/paplay） |
| KR4 部署准备 | 文档覆盖真机部署与排错 | `DEPLOY.md` + `DEVELOPMENT.md` 已更新 | 🟢 | 文档章节截图 |

**本周进展**
- 新增录音模块并接入唤醒后的指令匹配链路；
- 设计"录音+动作"双通道语义（口令既是动作也能播自定义语音）；
- 静音保护（RMS<300 丢弃）避免产生无效文件；
- 修复 SAPI 初始化失败时播放队列仍被使用的旧 bug。

**关键数据**
- 端到端测试 4/4 通过；新增代码覆盖 5 个 CLI 入口；文档新增 1 章。

**困难与风险**
- 固件不支持运行时修改唤醒词（`code=107`）→ 短期只能沿用"小微小微"；
- 在线 ASR 受限 → 依赖离线 Vosk，已作为**降级方案固化**；
- Linux 端交互录音依赖真实终端（termios），部署时需注意。

**下周计划**
1. RK3588 真机联调（唤醒→录音→ASR→MQTT→动作）；
2. `action.mode` 由 `mock` 切到 `mqtt` 生产模式验证；
3. 串口断线自动重连；
4. 扩充录音口令库。
